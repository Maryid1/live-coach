# 自部署说明

## 开发电脑

前提：Node.js 24、npm、Git 和 tar；先审查依赖及项目脚本。

```sh
npm ci
node scripts/package-selfhost.mjs
```

`npm ci` 按锁文件安装依赖；打包命令编译前端并生成 `outputs/live-coach-selfhost.tar.gz`。生成目录已被 Git 忽略，不包含真实 `.env`。

## Linux 服务器

安装 Docker Compose，将压缩包放在自己的用户目录。以下 `~/live-coach-test` 是示例部署目录：

```sh
mkdir -p ~/live-coach-test
tar -xzf ~/live-coach-selfhost.tar.gz -C ~/live-coach-test
cd ~/live-coach-test
umask 077
cp -n .env.example .env
chmod 600 .env
```

依次创建目录、解压、进入目录、限制新建文件权限、在不存在配置时复制示例、保护配置文件。已有部署应先备份，不能直接用初装流程覆盖其 compose.yaml。

用服务器编辑器填写 `.env`：APP_USER 为自定账号；APP_PASSWORD 至少 16 个字符。按需要选择一项：

| AI_PROVIDER | 必填变量 | 能力 |
| --- | --- | --- |
| bailian | DASHSCOPE_API_KEY、DASHSCOPE_BASE_URL、DASHSCOPE_MODEL | 搜索及三种答法 |
| deepseek | DEEPSEEK_API_KEY、DEEPSEEK_MODEL | 文本生成，未接入搜索 |
| zswing | ZSWING_API_KEY、ZSWING_MODEL | 固定第三方 Responses，未接入搜索 |

不配置模型密钥也可使用内置话术。示例中模型名和接口并非免费承诺，以服务商权限、协议和账单为准。一次只调用选定的服务商，不自动回退。

```sh
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
```

分别检查配置而不打印密钥、构建并后台运行、查看状态。配置检查报错应先修复，不继续启动。

包内默认监听服务器的 `127.0.0.1:3000`，不会直接开放公网。可在服务器本机测试，或由维护者配置 HTTPS 反向代理后访问。不要将登录账号和真实密钥放进 GitHub。

## 更新与验证

v5 新增服务器口播稿库。首次更新至 v5 必须添加 DATA_DIR 和命名卷映射，具体缩进、升级及数据备份见 `selfhost/UPDATE-v5.md`。旧版仅备份部署目录的方法不包含数据卷。不要运行 `docker compose down -v` 删除稿件。

更新前备份旧目录及配置；解压新版时保留服务器 `.env` 和自定义 compose.yaml。若新增服务商，需要同时更新环境变量映射，然后重新创建容器。历史 UPDATE 文档里的 `/home/admin` 是当时环境的示例路径，不应原样用于其他机器。

```sh
node node_modules/typescript/bin/tsc --noEmit --incremental false
node tests/coach.test.mjs
node tests/selfhost-ai.test.mjs
node tests/selfhost.test.mjs
```

在开发电脑执行：依次检查类型、内置话术、模型适配器模拟响应、打包服务登录与静态资源。最后一项需要先打包；模型测试不调用真实付费 API。真实连接需部署后由持有密钥的用户确认。
